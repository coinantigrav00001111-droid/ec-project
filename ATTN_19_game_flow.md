## 19.0. Концепт и границы

Сейчас игра запускается сразу в песочницу: главная сцена проекта (`GameRoot`) строит комнату и стол, интерфейс открывает Build. Главного меню, паузы, выбора макета, кампании и выхода нет. Для настоящей игры нужен цикл экранов, а для разработки нужен быстрый запуск любого экрана без прохождения меню.

**Решено в [ATTN_17](ATTN_17_ui.md) §17.12.3:** каркас потока, приоритеты (P1 игра и песочница, P2 главное меню, пауза и Model Studio, P3 кампания), `SceneRouter` и аргументы запуска.

**В объёме этого документа:** список экранов и переходов, что хранится между экранами, как запускать экран при отладке, порядок реализации.

**Вне объёма:** сами сцены экранов (макеты, дизайн, тексты: решаются в U7a и U17–U20 ATTN_17), содержание кампании (сценарии, цели, награды), онлайн, достижения.

## 19.1. Что есть сейчас

| Что | Где | Состояние |
|---|---|---|
| Игровая сцена | `data/scenes/game_root.tscn` (`GameRoot`) | главная сцена проекта (`run/main_scene`), запуск сразу в игру |
| Режимы игры | `ModeController`: Build, Operate, Observe, Library (заглушка) | работают, Library пуста |

## 19.2. Экраны

| id | Экран | Приоритет | Что на нём | Откуда и куда |
|---|---|---|---|---|
| `boot` | Загрузка | P2 | логотип, прогресс подготовки ресурсов (шейдеры, графика по `Settings`) | запуск → `menu` (или сразу `game`, если задан аргумент) |
| `menu` | Главное меню | P2 | Продолжить, Загрузить, Новая игра, Model Studio, Настройки, Выход | `boot`, пауза «в меню» → любой экран |
| `new_game` | Новая игра | P2 | выбор: Песочница или Кампания | `menu` → `sandbox_setup`, `campaign` |
| `sandbox_setup` | Настройка макета | P2 | название («Новый макет» по умолчанию), комната и стол, стиль траков | `new_game` → `game` |
| `game` | Игра | **P1** | Build, Operate, Observe; весь HUD из ATTN_17 | `menu`, `sandbox_setup`, `campaign`; в `pause`, `menu` |
| `pause` | Пауза | P2 | Продолжить, Сохранить, Загрузить, Настройки, В главное меню, Выход | поверх `game` (игра на паузе, не выгружается) |
| `load` | Загрузка макета | P2 | список сейвов: название макета, дата, снимок | `menu`, `pause` → `game` |
| `settings` | Настройки | P2 (U11) | окно поверх любого экрана | откуда угодно |
| `studio` | Model Studio (Library) | P2 | работа с одним объектом: ракурсы, иконки, потом редактор | `menu` → `menu` |
| `campaign` | Кампания | P3 | выбор главы → брифинг → игра → итоги → следующая или в меню | `new_game` → `game` |
| `exit_confirm` | Выход | P2 | подтверждение, если есть несохранённое | откуда угодно |

Для P1 ничего нового строить не нужно: `game` уже существует. Всё остальное накладывается сверху и не должно ломать запуск игры напрямую.

## 19.3. Схема переходов

```
Запуск → boot ──→ menu
                   ├─ Продолжить ───────────→ game (последний сейв)
                   ├─ Загрузить ──→ load ───→ game
                   ├─ Новая игра ─→ new_game
                   │                 ├─ Песочница → sandbox_setup → game
                   │                 └─ Кампания  → campaign → брифинг → game → итоги ─┐
                   │                                              ↑ следующая глава ───┘
                   ├─ Model Studio ─→ studio ──→ menu
                   ├─ Настройки (окно поверх)
                   └─ Выход → exit_confirm → конец

game ←→ pause (Esc): Продолжить | Сохранить | Загрузить | Настройки | В меню | Выход
```

Правило **[предложение]**: любой переход из `game` в другой экран идёт через проверку «есть несохранённое?» (один диалог: сохранить, не сохранять, отмена).

## 19.4. Архитектура

**`ScreenRegistry`** (ресурс `data/screens.tres`) **[предложение]**: список записей `{id, scene, priority, allow_pause, preload}`. Новый экран добавляется записью, а не кодом.

**`SceneRouter`** (автолоад) **[предложение]**:

- `go(id, params := {})` сменяет экран с короткой тёмной вставкой (U20). Параметры экрану отдаёт через `params`, а не через глобальные переменные.
- `push(id, params)` и `pop()` для экранов поверх (`pause`, `settings`, `exit_confirm`): нижний экран остаётся живым.
- сигналы `screen_changed(id)`, `screen_closing(id)`: на них подписываются автосейв и `Settings`.
- `current` и `stack` для отладки.

**Экран это сцена с узлом-корнем `Screen`** (базовый скрипт): `enter(params)`, `exit()`, `can_leave() -> bool` (вопрос о несохранённом). `GameRoot` получит тонкую обёртку `GameScreen`, внутренности игры не меняются.

**Что переживает смену экрана:** `Settings` (автолоад), `GFX` (автолоад). Игровой макет (`World`, сущности) живёт только внутри `game` и выгружается при уходе.

**Связь с интерфейсом игры (ATTN_17):** системное меню (U10) и пауза это одно меню в двух видах; кнопки «Сохранить», «Загрузить», «В меню» вызывают `SceneRouter` и `SaveManager`, а не друг друга.

## 19.5. Лёгкий запуск при разработке

**[предложение]** Аргументы запуска (Run with args, после `--`):

| Аргумент | Действие |
|---|---|
| `--screen=game` (по умолчанию) | как сейчас: сразу в игру |
| `--screen=menu`, `--screen=studio` | сразу на нужный экран |
| `--layout=reference` | загрузить эталонный сейв (`res://data/debug/reference.layout`) вместо пустого макета |
| `--fast` | как сейчас: без комнаты и карточек Observe |
| `--lang=en` | временно сменить язык (U7) |

Аргументы читает только `Global`/`SceneRouter` один раз при старте. Без аргументов игра запускается как сегодня, поэтому текущая работа с F5 в редакторе не меняется. Главная сцена проекта (`run/main_scene`) меняется на `boot` только когда он будет готов (шаг F4).

## 19.6. Что хранится между запусками

| Данные | Где | Когда пишется |
|---|---|---|
| Настройки (графика, клавиши, язык, подсказки) | `user://settings.cfg` (`Settings`) | отложенно, при изменении |
| Макет | `user://saves/<имя>.json` + снимок `.png` | по кнопке, автосейв при выходе |
| Метаданные макета | поле в сейве: `title` («Новый макет»), `created`, `saved`, версия игры | вместе с макетом |
| Последний сейв | `Settings` (`flow/last_save`) | при сохранении и загрузке |
| Прогресс кампании | отдельный файл `user://campaign.json` (P3) | при завершении главы |

Сейв по-прежнему хранит `setting_path` объектов (не id и не `key`): этот формат не меняется. Переименование макета двойным кликом в списке `load` (решение ATTN_17 §17.11 п. 5).

## 19.7. Пауза

**[предложение]** Пауза не останавливает физику вагонов в Observe (нужны кадры для съёмки), она останавливает симуляцию движения и ввод в мир. Что именно ставится на паузу (`process_mode`, физика, звук), отдельный список в шаге F3. Esc в игре: сначала закрывает то, что открыто (окно, выбор объекта, режим камеры), и только потом открывает паузу.

## 19.8. Model Studio

Прототип уже есть: Icon Studio ([ATTN_18](ATTN_18_icon_studio.md)). Как экран `studio` он получает своё окно и выход в `menu`. Название **[открыто]**: «Model Studio» или «Library» (ATTN_17 §17.12.12, п. 3). В игре кнопка Library в `ModePanel` остаётся заглушкой, пока Studio не станет полноценным экраном.

## 19.9. Кампания (P3, набросок)

Только рамка, чтобы данные не пришлось переделывать позже:

- глава это ресурс `Chapter`: `id`, название, брифинг (текст и картинка), стартовый макет (сейв), цели (список `Goal`), следующая глава;
- цель это условие на состоянии макета (построено N траков, поезд доехал до станции, вагонов на пути M): читает статистику TopBar (U9), а не обходит сущности сама;
- итоги главы: время, цели, оценка.

Требует отдельного обсуждения с GDD, пока ничего не строим.

## 19.10. План по шагам

Порядок по приоритетам. Шаги F идут после U10 и U11 из ATTN_17 (системное меню и окно настроек), потому что меню и пауза строятся из них.

#### F1. `SceneRouter` и `GameScreen`

**Цель:** игра запускается через роутер, поведение прежнее.

**Файлы:** новые `core/flow/scene_router.gd`, `core/flow/screen.gd`, `data/screens.tres`, `project.godot` (автолоад).

- [ ] `ScreenRegistry`, `SceneRouter.go/push/pop`, базовый `Screen`.
- [ ] `GameScreen` оборачивает `GameRoot`, без изменения его содержимого.
- [ ] Аргументы `--screen`, `--layout`, `--lang` (экран `game` по умолчанию).

**Проверка в редакторе:** F5 запускает игру как раньше; `--screen=game` то же; в Output нет ошибок роутера.

#### F2. Главное меню и выход

**Цель:** экран `menu` с кнопками, выход с вопросом о несохранённом.

- [ ] Сцена `menu`: Продолжить, Загрузить, Новая игра, Model Studio, Настройки, Выход. Недоступное серое (нет сейва: Продолжить).
- [ ] `exit_confirm` и `can_leave()` в `GameScreen`.
- [ ] `--screen=menu` открывает меню.

**Проверка в редакторе:** кнопки работают, Выход из игры спрашивает про несохранённое, только если оно есть.

#### F3. Пауза и сохранение макета с названием

**Цель:** Esc открывает паузу, у макета есть название.

- [ ] `pause` поверх игры (`push`/`pop`), что останавливается, по списку в §19.7.
- [ ] Поле `title` в сейве, «Новый макет» по умолчанию, `sandbox_setup` с этим полем.
- [ ] Список `load`: название, дата, снимок, переименование двойным кликом.

**Проверка в редакторе:** пауза не трогает вагоны в Observe; сохранить, выйти в меню, загрузить: макет и название на месте; старые сейвы без `title` открываются, получают «Новый макет».

#### F4. Загрузка и вход через меню

- [ ] Экран `boot` (прогрев шейдеров и графики).
- [ ] `run/main_scene` меняется на `boot` (с пропуском через `--screen=game`).

**Проверка в редакторе:** запуск без аргументов приводит в меню; с `--screen=game` сразу в игру.

#### F5. Model Studio как экран

- [ ] Icon Studio подключается как `studio`, выход в меню.

**Проверка в редакторе:** из меню открывается Studio, «Назад» возвращает в меню, игра в это время не работает в фоне.

#### F6. Кампания (P3)

После обсуждения с GDD: `Chapter`, `Goal`, брифинг, итоги.
